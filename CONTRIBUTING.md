# Trying an idea or contributing

You are welcome to experiment even if this is your first project. A small, well-explained change is useful.

## Make a version of your own

Fork the repository, run it locally and choose one thing to change. Start with `public/content.js` if you want to try a different activity or explanation.

Explain the learner or teacher need behind your change, then test a normal response and a difficult case. For a teaching activity, review the answer key, feedback and suitability for its learners.

## Suggest an improvement

Open an issue with what you tried, what you expected and what happened. Use fictional information in examples and screenshots.

For a pull request, include:

- The problem you are trying to solve.
- What you changed and why.
- How you checked it.
- A screenshot if the interface changed.

Run `npm test` and `npm run check` before submitting. For changes to a workflow, try the relevant browser interaction too.

Keep the interface accessible, preserve teacher review of writing and reasoning, and keep optional challenge marks separate from core learning evidence. Avoid adding actual learner records, credentials or claims of outcomes you have not measured.

If you mainly want to learn, a personal fork is enough. You can also share your experiment with Thomas through the contact links in the README.
